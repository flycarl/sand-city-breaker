# Project release policy

- Treat completed, user-approved game updates as release changes: verify them, commit them, and push them to the GitHub `master` branch so GitHub Pages deploys the live game.
- Do not publish features that are explicitly still being tuned, experimented on, or awaiting user approval.
- Before each release, run syntax/static checks, exercise the changed player path in a browser, and verify the GitHub Pages deployment after pushing.
- Preserve unrelated user changes already present in the working tree and include them only when they are part of the completed game update being released.
